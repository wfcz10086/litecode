# Windows 桌面与微信登录

已有 SSH 别名可直接在对话里说：

- 初始化 win11 并截图验收。
- 打开 win11 的微信，把扫码登录图片发给我。
- 我扫码了，检查 win11 微信登录状态并截图。

对应工具为 `windows_desktop(alias, action)`。初始化安装桌面依赖，其余操作不会安装软件。工具复用已有 SSH 密钥、跳板和 SFTP，在登录用户的交互会话启动临时计划任务，完成后删除计划任务。无需新增监听端口或保存 Windows 密码。

| 动作 | 参数与结果 |
| --- | --- |
| `initialize` / `screenshot` | 初始化并截图 / 获取真实截图 |
| `ocr` | 返回截图、识别文字、词级框合成的行边界框 |
| `click_text` | `text` 为完整 OCR 文字，唯一匹配后点击；返回前后截图，歧义时返回错误和当前截图 |
| `open_url` | `url` 为 HTTP/HTTPS 地址，在默认浏览器打开 |
| `type_text` / `hotkey` | `text` 输入当前焦点 / `keys` 执行支持的快捷键 |
| `windows` | 列出可见窗口的完整标题、进程和前台状态 |
| `scroll` | `amount` 负数向下、正数向上；可指定图片坐标，将鼠标放入目标滚动区域 |
| `click` / `drag` | 使用最新 `reference_image`、模型所见图片宽高及起止坐标，点击图标或拖动滚动条；自动换算物理像素，屏幕尺寸变化或截图超时拒绝操作 |
| `type_secret` | 用仓库外凭据引用 `credential` 和 `field` 输入，避免在参数中传密码 |
| `focus_window` / `close_window` | `title` 完整标题或最新 `window_handle` 唯一定位，支持同名窗口；普通关闭保留未保存提示，拒绝请求或仍可见不会误报已关闭 |
| `launch_app` | `name` 启动应用：内置 notepad/explorer/calc/mspaint/paint/edge/chrome；未知名称仅在节点开启 shell 能力后走开始菜单搜索（Win→输入→回车），关闭时拒绝；结果靠截图验收；cmd/PowerShell 属 shell 能力不在此启动 |
| `window_state` | 对 `title`/`window_handle` 定位的窗口 `window_state_mode` 最大化 / 最小化 / 还原 |
| `wechat_login` / `wechat_status` | 打开微信供扫码 / 按界面证据判断登录状态 |

截图与所有返回截图的动作支持 `compress=true`：按长边 ≤1600 缩放并转 JPEG（质量 70）提速传输；坐标换算仍以原始屏幕为准，原始屏幕尺寸记在上传截图同名 `.screen` 旁车文件里，点击 / 拖动定位不受影响。实测合成 2560×1600 渐变+UI 截图约降到 57%、像素数降到 39%；真实桌面大图（多为大面积纯色 / 文本的 PNG）降幅更明显。`ocr`/`click_text` 的识别仍在全分辨率原图上进行，只压缩回传给模型的图片。

结果的 `action_executed` 只说明动作已执行，任务是否成功必须用返回截图或后续 OCR 验收。任务执行过程沿用现有 SSE 工具开始、完成事件；Web 刷新后通过 chat_runs 重新跟随。图片用 `[发送图片: 路径]` 返回，现有微信桥接会把来源会话的图片上传给原发起人。Win11 个人微信已接通周期视觉巡检（见下文），常驻消息事件监听与自动回复仍未启用，不能用机器人桥接代替该能力。

最新桌面截图会以多模态图片进入下一轮模型输入，先补齐工具响应再附图；只保留最新自动观察图，图片 base64 不写入聊天历史。模型须先判断前台、遮挡层与滚动容器，目标不可见时滚动或处理遮挡，动作后根据新图验收。不存在特定网站的固定业务点击流程。Web 使用 `desktop_step` 卡片显示操作与截图，卡片随消息持久化，刷新后可查看。

`type_text` 和 `type_secret` 支持 `input_method=clipboard|unicode`。默认剪贴板粘贴；粘贴无效或输入法候选干扰时，模型可选择 Unicode 直接输入，不需要生成临时键盘脚本。发送成功仍须查看界面验证；只发送部分输入事件时报告失败，不能直接重发造成重复内容。

组合键采用带物理扫描码的 SendInput，并留出按键间隔，修复部分 Flutter 界面 Ctrl+A/Ctrl+V 不生效的问题。已在 Win11 实测全选、替换输入和客户端登录。支持窗口最大化、方向键、Home/End、删除、翻页和输入法切换。

## 系统运维与命令行（windows_system，仅主动回连节点）

除了视觉/OCR 通道，回连节点还有一条**命令行/非视觉通道** `windows_system(alias, action)`。能用命令完成的（查文件、看进程、装软件、读写配置）优先走它，比截图点击更快更稳；只有操作 GUI 应用（如 WPS 编辑文档）才用 `windows_desktop` 的 OCR + 点击。

| 动作 | 说明 |
| --- | --- |
| `system_info` | 系统版本、主机名、CPU 型号/核数/占用、内存、各磁盘容量/剩余、开机时长、登录用户 |
| `processes` | 按 `sort=cpu|memory` 排序的前 `top` 个进程，可按 `name` 过滤 |
| `kill_process` | 按 `pid` 或精确进程名结束；名称比较忽略大小写与 `.exe` 后缀。拒绝结束关键/常驻系统进程（System/csrss/wininit/winlogon/services/lsass/smss/svchost/dwm/sihost/fontdrvhost/MsMpEng/spoolsv/taskhostw/RuntimeBroker/ctfmon 等，见 `windows_system_actions.CRITICAL`）、会话 0 的服务进程和代理自身；按名称命中多于 1 个进程时拒绝并列出 pid，需改用 `pid` 或显式 `all=true`；结束 explorer 需 `force=true` |
| `services` | 只读列出服务及状态（代理普通用户权限，不做启停）；可 `name` 过滤 |
| `list_dir` | 列目录（名称/大小/修改时间/是否目录），最多 500 项 |
| `download` | 把 Windows 文件（≤50MB）取回服务端工作区 `uploads/` 并登记为产出物，返回服务端路径 |
| `upload` | 把服务端 `uploads/` 里的文件（`source` **必须**位于工作区 `uploads/` 目录内，≤50MB）发到 Windows 的 `%USERPROFILE%\Downloads\LiteCode\`，文件名清洗防穿越、同名自动加序号不覆盖 |
| `inspect_file` | **回读核对**：把 Windows 文件（≤50MB，路径支持 `%USERPROFILE%` 等环境变量）取回服务端并解析真实内容，见下文「回读核对」 |
| `run_powershell` | 执行 PowerShell：**默认关闭**，支持 `cwd`、返回 `exit_code`/`stdout`/`stderr`/`duration_ms`/`timed_out`，输出各截断 8000 字符，`timeout` 默认 60 秒上限 300 秒；超时用 `taskkill /T /F` 结束整个进程树，输出经临时文件收集，保证 timeout+15 秒内返回 |

`kill_process`/`upload`/`download`/`run_powershell` 是有副作用动作，执行后应回读（再 `list_dir`/`processes`/`system_info` 或截图）确认，不盲目重试。幂等只读动作（`system_info`/`processes`/`list_dir`/`services`/`inspect_file`/截图）遇网络类错误服务端自动重试 1-2 次；点击/输入/结束/传输类绝不自动重试。

### 回读核对（inspect_file + 收尾前回读闸）

真机案例（2026-10-17，gpu-vm）：模型用 WPS 表格做销售表，文件里 `D5=SUM(D2:D4)` 真实值 **1964**，它却从截图/OCR 读错数，汇报「合计 **4163** ✓ 已验证」。截图/OCR 不是文件真值，验收必须以文件为准。两层机制：

**第 1 层：`windows_system inspect_file path=...`**

- 服务端编排：复用 `download` 把文件分块取回服务端 `uploads/Node-Download-<id>-<名>`（副本**保留**以便事后审计，返回 `local_copy`；不登记为对话产出物），再在服务端用 `lib/doc_inspect.py` 解析。**节点端无新代码**，不涉及代理升级；版本门禁按 `download` 能力把关（`inspect_file` 在 `NEW_ACTIONS` 里，落后代理收到明确的「代理版本过低」）。SSH 别名不支持。
- 解析只用标准库 `zipfile` + `xml.etree`（不依赖 openpyxl/python-docx）：
  - **xlsx/xlsm**：各 sheet 名（workbook.xml + rels）、每个非空单元格的地址/公式（`<f>`，共享公式指回主单元格）/缓存值（`<v>`，共享字符串已解引用，布尔/内联字符串均处理），每 sheet 最多 200 格；另给 `formulas` 列表（sheet/地址/公式/缓存值）。公式无缓存值时标注「文件未重算保存」。
  - **docx**：`word/document.xml` 段落文本（按 `<w:p>` 拼 `<w:t>`），段落数、非空段落数、字数（中文按字计，英文/数字按词计）。
  - **pptx**：按 `ppt/presentation.xml` 的 `sldIdLst` 顺序（经 rels 解析到 slideN.xml，**不按文件名排序**）输出每页文字与页数。
  - **txt/csv/tsv/md/json/log**：UTF-8 解码失败回退 GBK，返回前 8000 字。
  - **其他**（含 .xls/.et/.pdf）：只返回大小/sha256/类型，说明不解析。
  - 安全：成员数上限 5000、单成员解压后 20MB 上限（实际读取再限一次）、声明总量上限、拒绝带 DTD/实体声明的 XML；损坏文件返回 `{"ok": false, "error": "..."}` 而非异常栈。
- 只读：在 `IDEMPOTENT_ACTIONS`（网络错误可重试）和循环守卫 `_GUI_OBSERVE`（反复核对不计循环）里。
- 工具描述要求：界面改过/保存过的文件，汇报前必须 `inspect_file` 回读；数字、文字以其结果为准，不以截图为准。

**第 2 层：收尾前回读闸（`lib/agent/readback_gate.py`，开关 `agent.readback_gate`，默认 true）**

- 追踪本回合工具调用（`after_tools` 每批之后观测，同批内按调用顺序）：
  - **文件改动类**（才会触发）：快捷键 `ctrl+s`/`ctrl+shift+s`/`f12`（保存、另存为）、`ctrl+v`/`ctrl+x`（粘贴、剪切）、`delete`、`f2`（重命名），`drag` 拖拽，以及 `click_text` 点中「保存/另存/粘贴/剪切/删除/重命名」等字样。纯打字、回车、普通点击（如在微信里发消息）不产出文件，**不触发**。按坐标点击工具栏保存图标识别不了，靠工具描述里"改过文件必须 inspect_file"兜底。
  - **回读类**：`windows_system` 的 `inspect_file`/`list_dir`/`run_powershell`/`download`，且结果不是 `ERROR`/被守卫拦截。
- 模型给出最终文本回复（无 tool_calls）时：本回合用过 `windows_desktop`、有改动、且**最后一次改动之后没有成功的回读** → 不结束回合，注入一次：

  > [SYSTEM-READBACK] 你在界面上修改/保存过文件, 但之后没有回读核对。请用 windows_system 的 inspect_file (或 list_dir/run_powershell) 读取实际文件内容, 用真实数据核对你将要汇报的结论 (尤其是数字), 再给出最终总结; 若确实没有产出文件, 说明原因后直接总结。

- 每回合最多一次，第二次总结直接放行（不死循环）。开关关闭时 observe/check 都是空操作，零行为变化。
- 注入走 `[SYSTEM-...]` 约定：Web 会话转换（`web_ui._is_sys_inject_text`）不显示；记忆提取输入（`turn_persist.memory_input`）剥掉 `[SYSTEM...]` 伪 user 消息。
- 已知局限：被拦下的第一版总结已经流式发给用户，用户会先看到它、再看到回读后的更正版；子代理（spawn_agent）内部循环不经过本闸。

### 多台电脑并行：远程操作员子代理（operator）

主代理可以用 `spawn_agent` 派发 `agent_type="operator"` 的子代理，每个操作员负责**一台**电脑，多台电脑同时干活：

```
spawn_agent(parallel_tasks=[
  {"agent_type": "operator", "alias": "vm-a", "task": "在桌面新建 报告.txt 写入'A 完成'并保存"},
  {"agent_type": "operator", "alias": "vm-b", "task": "用 WPS 打开 D:/sales.xlsx, 在 D5 填 =SUM(D2:D4) 保存"}])
```

- **角色**：工具只有 `windows_desktop`、`windows_system`、`read_file`、`vision_ocr`；不能 `execute_shell`、不能写服务器文件。max_iter 60，默认超时 1200 秒。提示词要求：先截图观察 → 每步动作后截图/OCR 确认 → 能用 windows_system 命令行完成的优先命令行 → 改过文件必须 `inspect_file` 回读并以回读为准 → 只操作分配的 alias。
- **必须指定 alias**：任务项 `alias` 字段（或 spawn_agent 顶层 `alias` 作默认）。缺 alias 直接拒绝派发。
- **一台电脑同一时刻只归一个操作员**（只有一套鼠标键盘）：
  - 同时运行的两个 operator 指定同一 alias（parallel/competitive，或 DAG 中无依赖先后的步骤）→ **拒绝整个派发**，提示把同一台电脑上的事合并成一个任务，或用 `pipeline_tasks` / `depends_on` 串行。管道、批量、有依赖的 DAG 步骤允许同一 alias。
  - 运行时按 alias 加 `asyncio.Lock`：不同派发/不同会话的操作员抢同一台电脑时排队，最多等 `agent.operator_lock_wait` 秒（默认 120）。
  - 操作员占用期间，主代理或其他会话对这台电脑的 `windows_desktop` / `windows_system` 调用**立即报错**（"节点 X 正被操作员子代理独占"），不排队，避免主代理等自己的子代理形成死锁；其它电脑不受影响。
  - 操作员调用 windows 工具时 alias 与分配的不同 → 拒绝；没填 alias → 自动补成分配的。
- **截图回流**：操作员每次 `windows_desktop` 返回截图后，下一轮模型输入附上最新一张截图（与主循环 `[DESKTOP_OBSERVATION]` 同一实现）；当前模型不支持视觉时按配置路由到 `vision_fallback_id` 或剥图。`reference_image` 自动补的是该操作员自己的最近截图（按子代理独立 sid 记录），不会用到别的操作员或主代理的截图；操作员开工时清掉其他会话手里这台电脑的旧截图。
- **交付证据**：operator 属写类。界面改过文件（保存/另存/粘贴/剪切/删除/重命名/拖拽，与回读闸同一判定）或 upload 过文件，最后一次改动后必须有成功的 `inspect_file` / `list_dir` / `run_powershell` / `download` 回读才标 `[已验证]`，截图/OCR 不算；只做界面操作没改文件的，最后一次操作后有 screenshot/OCR 确认即可。未验证时注入一次补证提示。
- 局限：操作员截图登记在子代理自己的会话下，不会作为产出物出现在主会话里（结果文本里有图片路径）；主循环的收尾回读闸不作用于子代理内部，由证据判定兜底。

### 命令行能力开关（run_powershell）

`run_powershell` 是用户主动要的一等功能，但默认关闭、最小权限：

- **只能由用户开启**：Web 新建节点时勾选「初始化时允许 PowerShell 命令执行」（默认不勾选），接入后使用节点面板「开启命令行能力」按钮，或 CLI `litecli nodes shell <别名> on|off`；都需要 Web 登录（`require_management`）。**工具层没有任何开启入口，模型不能给自己开权限**。
- **认证沿用现有设备凭据**：不发明新密钥体系。开关状态存在服务端节点记录里，经设备**已认证的 Bearer 轮询通道**下发给节点；节点在执行 `run_powershell` 前用这份能力做**本地二次校验**，开关没开就拒绝。服务端也独立校验：未开启不下发该动作。
- **输出中文正确**：固定前缀设 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`（中文 Windows 默认 GBK/OEM 会乱码），Python 侧按 UTF-8 解码、失败回退 GBK。
- 仅对开启了 shell 能力的回连节点可用；SSH 别名不支持（SSH 本身已是 shell）。

#### 开关的真实边界（2026-10-17 加固）

- **开关状态带签名，文件写入类工具改不动**：节点记录 `nodes.json` 位于工作区 `.secrets/windows_nodes/`，而模型的 `write_file`/`patch_file`/`apply_blocks` 能写任意路径（没有路径白名单），所以只“挪位置”挡不住。现做法是完整性校验：`shell=true` 只有带上有效 HMAC-SHA256 签名（`capabilities_sig`，绑定节点 id）才算开启，签名密钥 `capability.key.bin` 只由经过管理认证的初始化授权/开关接口生成；缺签名/签名不符/密钥缺失或损坏一律按**关闭**处理（失败即关闭）。密钥文件是以 NUL 开头的二进制 `.bin`，`read_file` 按二进制拒读；**每次开关都换新密钥并按旧密钥核验后全部重签**，开启时抄下的旧记录在关闭后回写（重放）也无效，被篡改的记录在下一次开关时归零。服务端派发校验、轮询下发给节点的 `capabilities`、Web/CLI 列表看到的都是校验后的值，列表不返回签名字段。
  - 选它而不是“挪位置”的理由：同一进程用户下没有模型写不到的目录；签名只需改 `lib/windows_nodes.py` 一处，开关仍只有管理员接口一个写入口。
  - **升级影响**：升级前已开启、没有签名的节点会读成关闭，需管理员在 Web/CLI 重新开启一次。
  - **不在此边界内**：能在服务器上执行任意代码的工具（如 `execute_shell`）本就可以直接调用管理代码或改源码，开关无法防它；该边界针对的是文件写入类工具。
- **开关关闭时桌面动作不能旁路启动命令行**：
  - `launch_app` 只接受内置白名单（notepad/explorer/calc/mspaint/paint/edge/chrome），**不再用开始菜单搜索任意名称兜底**；cmd/PowerShell/终端名称无论开关如何都拒绝（请用 `run_powershell`）。
  - 直接打开“运行”对话框的快捷键 `win+r` 不可用。
  - 开关打开后放开：未知名称恢复开始菜单搜索，`win+r` 可用。
  - 双层校验：服务端派发前按校验后的开关拦（SSH 别名没有开关，按关闭处理）；节点代理按已认证轮询拿到的能力，在请求里**覆盖写入** `shell_allowed`，桌面组件据此再拦一次（服务端组装请求从不带该字段，模型也无法经工具参数注入）。
  - 兼容：旧代理不认识 `shell_allowed`、只拿到新组件时按关闭处理（只会更严，不会放宽）；旧组件收不到被禁止的请求，因为服务端先拦。`launch_app` 本就只下发给最新代理。
  - 残余：这条边界是“动作层”的，不等于 GUI 级隔离——用白名单里的资源管理器地址栏、任务管理器“运行新任务”、或点开始菜单再输入，仍可能经点击/输入拉起命令行。需要硬隔离的电脑应在 Windows 侧用组策略（禁用命令提示符/AppLocker）兜底。

### 文件传输分块协议

传输走现有任务通道。单块原始 4MB（base64 后约 5.3MB，远低于请求体 24MB 上限），整体 sha256 校验：

- **upload**：服务端把 `uploads/` 里的文件按 4MB 切块，逐块下发；节点追加写到 `Downloads\LiteCode` 下的 `.part-<transfer_id>` 临时文件，最后一块校验整体 sha256 后改名为唯一文件名。源文件**只允许工作区 `uploads/` 目录内**（相对路径按 `uploads/` 解析，不按服务进程当前目录；`resolve()` 真实路径后判断，挡住 `../` 穿越与指向 `uploads/` 外的符号链接逃逸）——工作区根目录下还放着 `.secrets/`（Windows 凭据）、`sessions/`（会话）、`logs/`、`telemetry/` 等内部目录，收紧到 `uploads/` 后这些文件无法被 upload 外泄到 Windows 节点。`download`/`inspect_file` 的落地目录本就是 `uploads/`，不受该限制影响。中断的上传会留下 `.part-*`：节点在每次新上传开始（第 0 块）时清理修改时间超过 1 小时的 `.part-*`（进行中的传输每块都会刷新 mtime，不会误删）。服务端失败时不额外下发清理任务——旧代理不认识新的清理动作，且清理只差下一次上传，取舍为只做节点端清理。
- **download**：节点无状态（任务目录每次执行后删除），先回元数据（size/chunks/sha256/name），再按偏移逐块重读回传；服务端重组并校验 sha256 后落到 `uploads/`。

## 向后兼容与版本门禁

新动作（系统运维、文件传输、`launch_app`/`window_state`）只有在节点运行**最新版本代理**时才下发；版本落后的已部署节点收到新动作会得到明确的「代理版本过低，等待自动更新」错误，而不是挂起，待其空闲自动更新后即可用。老代理忽略轮询响应里新增的 `capabilities` 字段，行为不变。新增的 Windows 端文件（`windows_system_actions.py`/`windows_file_actions.py`/`windows_transfer.py`）已进入下发清单（`WORKER_FILES` / 代理 `ASSETS` / 路由 `ASSETS` / SSH 上传），两端按相同字节算版本哈希。

## 周期巡检

LiteCode 定时器 `action_type=agent` 已接入现有 Web 后台轮次。定时器明确指定原会话 sid，工具创建时省略目标则继承当前 sid；目标会话忙时跳过本次，不抢占、不并行操作桌面。定时历史的“已启动”只表示派发成功，实际执行结果、截图和错误仍看原 Web 会话。无需额外对外监听端口。

可创建 `*/2 * * * *` 的 agent 巡检任务，目标为原 Web 会话，由模型观察真实画面并对比工作区中的水位文件。已实测：发送一条消息、识别一条新回复、下一轮不重复播报。周期视觉巡检未启用群自动回复；可在 Web 定时任务中停用，或对话要求停止监听。关闭全部窗口前应先停用对应巡检，避免重新唤起应用。

图片下载至工作区 `uploads/`，作为产出物记录，并返回 `[发送图片: 路径]` 供对话展示。微信状态以明确 UI 控件为证据；`unknown` 不代表成功。二维码及界面截图属于账户数据，按工作区现有访问权限和保留策略管理。

## 新机器接入

### 纯净 Windows：主动回连（推荐）

在 LiteCode Web 左侧展开“接入”→“添加 Windows”。电脑代号自动生成，可以修改。接入地址自动取当前 Web 地址，首次接入时确认新 Windows 可以访问；`localhost` 和 `127.0.0.1` 不能作为另一台电脑的入口。公网必须使用 HTTPS；内网 HTTP 仍是明文传输，页面会提示，长期使用也应配置 HTTPS。

点击“生成接入命令”并复制，在当前使用的 Windows 用户桌面，右键开始按钮打开终端（管理员），粘贴执行。十分钟内的一次性接入码把这台电脑绑定到刚创建的节点；设备主动回连后，Web 自动显示电脑名、登录用户、安装阶段和首张截图，无需扫描局域网或手填设备 IP。命令使用过后，在同一用户下重跑可继续未完成的安装。

引导脚本准备每节点独立的 Python 运行时及 venv，已有 Python 只作为基础文件复制来源，依赖装入节点目录。没有可用基础运行时时下载、验证官方安装器，安装到节点自己的目录并保留卸载器。桌面代理以安装用户的交互会话运行，开机/登录触发；主动回连通道不依赖 SSH 入站连接。

初始化同时检查并安装 Windows OpenSSH Server，将 `sshd` 设为 Automatic 并启动。控制端为每个新节点生成独立 Ed25519 密钥，私钥保存在 `.secrets/windows_nodes/ssh/<节点ID>`（0600），安装命令只携带公钥，写入安装管理员使用的 `administrators_authorized_keys`。本次新装的 SSH 禁用密码认证，新建入站规则仅允许 LocalSubnet；已有 SSH 的配置、密码认证及防火墙策略保留。异地访问需要实际可达的可信隧道或单独配置管理来源地址；安装 SSH 不会自动建立隧道，也不保证公网直连。

桌面工具的 `shell` 开关控制节点动作通道，**不限制独立 SSH 连接**；SSH 公钥对应 Windows 账户的系统权限，管理员密钥等价于管理员后台访问能力。应保护控制端和 SSH 私钥。撤销/删除节点时控制端删除本节点 SSH 私钥；设备确认撤销后尝试移除自己的公钥，完全卸载时必须移除自己的公钥。共享 SSH 服务、已有密钥及防火墙环境保留，避免破坏其它连接。

设备使用出站长轮询领取已注册的桌面动作，执行后上传结果与截图。Web 每三秒更新连接和安装状态；超过九十秒未收到连接则显示离线。“在线”与“桌面可操作”分开显示，锁屏或未登录明确要求用户解锁。点击“检查桌面”重新验收；“在对话中操作”填入该电脑的截图请求，用户发送后沿现有聊天流程执行。最近动作区分等待领取、执行中、已返回、失败、未确认，`ok=true` 只代表动作返回，不证明消息已送达或业务已完成，模型仍须观察截图验收。任务超时不自动重发，避免重复发送消息。

对话工具 `windows_nodes` 支持 create/list/revoke/uninstall，操作桌面继续使用 `windows_desktop(alias=...)`。生成命令不代表设备已经接通，领取任务也不代表任务已经完成。

### 凭据与安全边界

- 设备的接入码仅首次登记可用，服务器保存 SHA-256 摘要。每台设备领取独立随机凭据，服务器同样只保存摘要；设备凭据不能管理其他节点。
- Windows 在 `%LOCALAPPDATA%\LiteCodeNodes\<安装标识>\node.json` 保存 DPAPI CurrentUser 加密后的设备凭据，并限制目录 ACL；代理仅在内存中解密。旧的明文设备配置需重跑安装命令迁移。DPAPI 不能阻止已经能以同一 Windows 用户或管理员身份执行代码的攻击者。
- 管理接口要求 Web 登录；关闭 Web 登录保护时节点管理接口拒绝操作。节点接口响应带 no-store，设备凭据不写入 URL。撤销使后续认证失败并清除未完成任务；已执行的动作无法撤回。
- 应用自身登录态由微信、浏览器等应用保存在 Windows 用户目录中。手工保存的应用密码仍位于控制端仓库外的 `.secrets/windows_credentials.json`，当前文件权限为 0600，尚不是完整的加密凭据库。待输入密码可能短暂存在受 0600 保护的任务文件中，派发后移除。
- 当前代理具有安装用户的最高权限，因此 LiteCode 管理账户及服务器属于可信控制端。不能因为使用了设备凭据和 DPAPI 就声称已完成全面安全审计。HTTP 内网连接不能提供传输机密性；下发代码的完整性由安装命令锚点 + 签名清单保证，见下文「代码下发完整性」。

### 版本与自动更新

控制端按实际下发的字节计算代理与桌面组件版本（内容哈希前 16 位），随每次轮询返回；设备每次轮询上报正在运行的版本，Web 节点卡片显示“运行版本”。设备空闲时：组件过期即重新下载并丢弃已导入模块，下一次桌面动作使用新代码，无需重启；代理本身过期则下载新代理，哈希与控制端公布一致才原子替换，再借计划任务重启自己。哈希不一致不替换，同一目标版本只尝试一次，避免重启循环。执行中或待回传的动作不会被更新打断。

组件更新是**全有或全无**：先把全部组件下载到节点目录下的 `.update\` 临时目录，按轮询响应新增的 `asset_hashes`（逐文件完整 sha256）逐个校验，再核对整体版本哈希，全部通过才逐个 `os.replace` 到位；任一下载失败或哈希不符则放弃本次更新，旧文件原样保留。代理启动时先请求 `/versions` 拿到公布版本再加载；校验不符但本地已有完整旧组件时先用旧组件。卸载脚本 `uninstall.ps1` 也在更新清单里（`WORKER_FILES` / 代理 `ASSETS` / 路由 `ASSETS` 三处一致，有测试防漂移），落盘时补 UTF-8 BOM 以便 PowerShell 5.1 正确读中文，版本哈希按下发字节（不含 BOM）计算。

节点处于 `updating`（上报版本与控制端不一致，自动更新进行中）时下发新动作，服务端最多等待 90 秒（每 2 秒查一次节点状态，在工具线程里等，不阻塞事件循环），节点以新版本回连后再下发；超时才报“节点正在更新，请稍后重试”。`legacy`（不上报版本的旧代理）仍立即报“代理版本过低”。

### 代码下发完整性（安装锚点 + 签名清单，2026-10-17）

内网 HTTP 接入时，“期望哈希”和文件本身走同一条明文通道，途中被替换时哈希会被一起替换，单靠哈希起不到保护作用。现在的信任链从**管理员带外复制的命令**出发（命令不经过节点与控制端之间的网络，因此可信）：

1. **安装命令携带锚点**：一次性安装命令里有 `$h='<bootstrap.ps1 的 sha256>'` 和 `-KeyFingerprint '<签名公钥指纹>'`。命令先按字节下载 `bootstrap.ps1`，sha256 与 `$h` 不一致就抛出「安装脚本校验失败……已停止，未执行任何安装步骤；请让管理员重新生成安装命令」，不执行脚本。控制端升级了引导脚本后，旧命令会因此失效，重新生成即可。
2. **引导脚本校验公钥再接入**：引导脚本在消费接入码之前下载 `/api/windows/signing-key`，按 `sha256("<alg>:<n>:<e>")` 计算指纹，与命令里的指纹不一致即停止。下载 `agent.py`、`uninstall.ps1` 后，用该公钥（.NET `RSACryptoServiceProvider`）验签控制端清单并逐个核对 sha256，全部通过才写入；最后把公钥写入节点目录 `trust.json`（`pinned_by=install`）。
3. **自动更新只认签名清单**：控制端用私钥签名清单 `{format, issued, versions, files: 代理与全部组件的完整 sha256}`，随 `/versions` 和每次轮询以 `signed_manifest` 下发（旧字段 `versions`/`asset_hashes` 保留给旧代理）。已固定公钥的代理只采用验签通过的清单：组件每个文件都必须有清单哈希且一致、整体版本一致，代理自更新要求完整 sha256 一致；验签失败、清单缺失、只给未签名哈希、任一文件不符都**不替换任何文件**（组件仍是全有或全无），启动时退回本地已有组件并在 `state.txt` 记下拒绝原因。清单里的 `issued` 低于已接受清单的不再接受，防止回放旧版本降级。
4. **HTTPS 下行为不变**，验签照样叠加。

**签名方案**：RSA-3072，PKCS#1 v1.5，SHA-256。私钥只在控制端工作区 `.secrets/windows_nodes/signing_key.pem`（0600，首次需要时用 `cryptography` 生成），从不下发；公开接口只返回公钥 `{alg, n, e}` 与指纹。选 RSA 不选 Ed25519 的理由：节点 venv 只装了 mss/pillow/uiautomation/pywin32/pyautogui/pyperclip/winocr/psutil，没有任何密码学库，Python 标准库也只有哈希/HMAC；RSA 验签只需一次 `pow` 加整体比较期望编码（`windows_node_agent.rsa_verify`，十几行纯标准库，不解析填充），Ed25519 要在节点端手写曲线运算；安装阶段运行在 PowerShell 5.1/.NET Framework，原生能验 RSA、不支持 Ed25519。控制端缺少 `cryptography` 时不下发签名清单，安装命令只带脚本 sha256，旧的哈希校验照旧（日志告警）。

**本机更新/卸载命令**同样带锚点：「本机更新命令」带当前代理的 sha256 与公钥指纹，下载内容不符不替换，并顺便把公钥写入 `trust.json`（`pinned_by=update_command`）；「本机卸载命令」在本地脚本缺失、需要从 Web 下载时核对卸载脚本 sha256。

**已上线旧节点的迁移（首次信任窗口）**：签名上线前安装的节点没有 `trust.json`。它们照旧通过现有方式（同一通道公布的哈希）自动更新到新代理——**这一次代理更新本身没有签名保护**；新代理启动时发现没有固定公钥，就经已认证的设备通道 `/api/windows/device/<id>/signing-key` 取一次公钥写入 `trust.json`（`pinned_by=first_use`），从这一刻起所有组件与代理更新都要求验签，之后途中再换公钥也不会覆盖已固定的公钥。所以首次信任窗口是：「旧代理 → 新代理」这一次更新，加上新代理首次取公钥的那一次请求。对此不放心的内网节点，可以在可信网络下完成这次升级，或改用 Web 的「本机更新命令」/重跑新安装命令（公钥由命令里的指纹锚定，不经过首次信任）。控制端尚未支持签名（返回 404/503）时代理不固定任何公钥，继续旧方式。

**运维注意**：签名私钥丢失或更换后，已固定旧公钥的节点会拒绝所有更新（但继续用现有代码工作），需在该电脑上重跑新生成的安装命令或执行「本机更新命令」重新固定公钥。`trust.json` 损坏时代理拒绝一切更新，不会降级为不验签。HTTP 内网连接仍然没有传输机密性：设备凭据、任务参数与截图依旧明文，签名只保证**下发代码**的完整性。

2026-10-16 之前安装的代理不上报版本，卡片显示“旧版代理”，需要在该电脑上用安装时的用户、管理员 PowerShell 执行一次 Web 提供的“本机更新命令”（本地用 DPAPI 读出设备凭据，不经 URL 传递），之后即可自动更新。重跑原安装命令也会先停掉旧代理再启动新代理。

### 断线、锁屏与自启

- **网络断开**：代理按 2 秒起、最长 60 秒的退避无限重连，恢复后自动上线。断线期间未回传的任务过期后不自动重发，避免重复发送消息。
- **进程异常**：计划任务崩溃后每分钟重启、最多 999 次；另有每分钟一次的补拉触发器，覆盖未被系统判为失败的进程退出；用户会话仍存在时，下一个触发周期会尝试重新拉起（运行中由 IgnoreNew 忽略，不会多开）。旧安装由代理启动时自行补齐这份配置。凭据被撤销时代理停用自己的计划任务，不再空跑。
- **撤销判定**：控制端只在真正认证失败（凭据不符、节点已撤销或删除，`AuthError`）时返回 403，并带响应头 `X-LiteCode-Auth: revoked`；其他异常（任务文件损坏、磁盘错误等）返回 500。代理只有**连续 3 次**收到带该标记的 403 才停用计划任务；裸 403（反向代理/WAF）和 5xx 一律按网络错误退避重试。损坏的任务文件会移到 `.secrets/windows_nodes/quarantine/` 并记日志，不影响其他节点；`nodes.json` 与任务文件写入走临时文件 + fsync + `os.replace`。遍历任务文件时容忍并发删除（`wait()` 不持锁删除任务文件，遍历遇到 `FileNotFoundError` 直接跳过）。
- **长轮询负载**：poll/result/list 中的加锁读写、base64 解码与图片校验放在 `asyncio.to_thread`；`nodes.json` 内容没变就不回写，空闲心跳的 `last_seen` 每 15 秒才刷新一次（离线判定阈值 90 秒）。
- **桌面就绪状态**：只有带截图的结果（或明确的 `desktop_unavailable`）才更新“桌面可操作”；系统/文件/传输类动作不改它。
- **大截图**：代理端单张截图超过 8MB（4K/多屏 PNG）时自动转压缩 JPEG 再上报（与 `compress=true` 同一机制，`screen_size` 写 `.screen` 旁车，点击坐标换算不受影响），避免超过控制端单图 12MB / 请求体 24MB 上限。
- **鼠标角落**：pyautogui 的 FAILSAFE（鼠标在屏幕角落时每个动作都抛异常）已关闭，避免上一个动作把鼠标留在角落后所有动作持续失败。
- **工作目录**：计划任务启动的进程 cwd 是 `C:\Windows\system32`，导致代理拉起的记事本/WPS“另存为”默认跳到 System32。新安装的计划任务带 `-WorkingDirectory`（节点目录）；代理启动时 `chdir` 到用户主目录（已安装节点无需重装）；`launch_app` 内置映射以“文档”目录（含 OneDrive 重定向，不存在则主目录）为工作目录启动应用。
- **锁屏**：代理保持在线，桌面动作返回 `desktop_unavailable`，Web 显示“已连接但桌面锁定”。当前工具不操作登录安全桌面，也不提供自动解锁；需要通过 Windows 正常登录流程恢复桌面。用远程桌面连过这台电脑再断开，会话同样进入锁定状态；断开前可在该会话的管理员终端执行 `tscon %sessionname% /dest:console` 把会话交回本机控制台，保持可操作。
- **开机**：新安装配置开机、安装用户登录和每分钟补拉三个触发器（运行中忽略重复启动）。任务以安装用户的 Interactive 会话运行，重启后进入该用户桌面即可自动回连；未登录时不提供后台服务，锁屏时不执行桌面操作。LiteCode 不修改自动登录、锁屏或屏保设置。[Windows 触发器说明](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasktrigger)。

### 开机自启与代理、功能包热更新

一键接入会同时安装启动任务、节点代理和桌面/OCR/系统/文件组件。支持自动更新的旧节点在控制端发布新代理后，空闲时自动升级并迁移启动配置，无需重新消费接入码；不上报版本的早期节点仍需执行一次 Web 提供的“本机更新命令”。

- **启动修复**：每次代理启动、运行期间每小时，重新检查并配置启动任务的触发器、独立 Python 路径及工作目录；任务缺失会重建，管理员明确禁用的任务保持禁用。崩溃自动重启和每分钟补拉沿用现有机制。
- **功能包热更新**：只在没有正在执行或等待回传结果的动作时更新。全部下载、签名/哈希校验和 Python 语法检查通过后，备份旧组件并记录恢复信息，再替换文件。替换中途失败立即恢复；进程在替换期间被终止，下次启动先恢复旧组件，再连接服务器、接收任务。回滚也失败时保留恢复信息并暂停接任务，等待恢复成功。
- **代码缓存**：更新后清理相关模块缓存及旧 `.pyc`，同一秒内发布同长度代码也会使用新版本；下一次动作使用新组件，组件更新不要求重启代理。
- **代理自更新**：代理代码通过哈希及语法检查才替换，并保留 `agent.py.previous`。重启助手在独立的 `LiteCode-Update-<id>` 计划任务中运行，等待旧进程和旧节点任务退出 Running 后启动新版，最后删除自己的任务及脚本；注册或启动助手失败时恢复旧代理。普通子进程仍属于旧任务进程树，会造成双方互等，已在 Windows 真机排查中修复。这里的恢复不等于对任意运行时错误提供健康检查回滚。

重启/断网不会使已接入节点的设备凭据过期：断网后代理退避重试；关机时不运行，重新开机进入安装用户会话后回连。SSH 服务可在用户登录前启动，仍需要网络路由/隧道就绪。锁屏后文件/系统动作仍可执行，GUI 动作返回 `desktop_unavailable`，当前不会自动等待解锁续跑，也不会自动解锁。需要无人值守 GUI 时可由所有者在专用虚拟机上选择自动登录并保持桌面可用；个人电脑可保留锁屏，解锁后重新检查再继续。[微软 Autologon 说明](https://learn.microsoft.com/en-us/sysinternals/downloads/autologon)。

### SSH、OCR 与 VS Code 混合使用

SSH/系统通道处理文件、命令和容器，桌面通道处理 GUI。两者可以串行交替使用，先核对它们对应同一台 Windows。SSH 拉起的程序可能位于后台会话；交互应用通过 `launch_app` 启动，并依据窗口列表确认前台焦点。

收尾前的文件回读按电脑别名分别确认；另一台电脑的文件不能抵消本机的待核对修改。缺失或明确失败的工具结果不算成功回读。SSH 命令超时返回 `rc=124` 并提示远端完成状态未知；先检查实际进程状态，再决定是否重试安装或其它有副作用命令。

Windows SSH 脚本可使用 `ssh_exec(shell="powershell", cmd="原始脚本")`，编码和 UTF-8 输出由工具处理；PowerShell 5.1 多句用换行或分号。OCR 可传 `ocr_language="en-US"`，支持的语言由 `available_languages` 返回。界面英文代码和数字可以选择已安装的英文引擎；OCR 仍可能误识别，保存结果必须回读文件内容。OCR 验收可传 `expected_texts=["完整预期行"]`，仅忽略空白，大小写和数字必须一致；任一行不匹配会返回 `ok=false/state=ocr_mismatch`，不能报告识别通过。`click_text` 每次重新 OCR，找不到或重名时拒绝点击；截图压缩后仍按原始屏幕坐标执行。

新增实验入口 `shell="wsl"`、`wsl_distro` 与可选 `wsl_user`，用于通过 Windows SSH 执行原始 Bash：脚本经 stdin 传输，统一 UTF-8/LF，分流输出并保留原生退出码。本地 PowerShell/SSH/工具注册相关用例 40 项通过；LiteCode Web 发起的 Windows 原生验证出现超时，尚未通过，已暂缓并保留证据，不用于开发主线。运行中的后端未加载新签名；后续验证可通过技能的 `assets/run-wsl.py` 独立进程调用新代码。

`launch_app` 增加 `vscode` / `code` 默认安装目录支持；命令面板、跳转行及 F9/F10/F11 等调试快捷键可用。代理执行长任务期间每 20 秒独立发送存活心跳；这只证明节点在线，不代表动作完成，也不会重复执行动作。

### 完全卸载

Web 的“完全卸载”与“撤销接入”分开。完全卸载停止新任务，清除待执行队列；在线电脑收到卸载指令后建立独立清理任务，停止并删除代理计划任务，移除专属运行环境（安装器安装的运行时先运行官方卸载器），删除节点目录及加密凭据，最后删除清理任务和临时卸载脚本。已有 Python、其他节点、微信和 Chrome 等应用不属于清理范围。

只有设备回传清理完成后，Web 才显示“已完全卸载”，服务器移除设备凭据并保留不含凭据的卸载结果。历史对话和任务截图按原有工作区保留规则处理。离线显示“等待电脑接收卸载”，收到指令后显示“等待清理回执”，清理失败显示“卸载未完成”；不将请求已发送当成卸载成功。

本机可以复制 Web 的“本机卸载命令”，在安装时的用户下用管理员 PowerShell 执行。命令优先调用本地已安装的卸载脚本，可在无法回连 LiteCode 时清理本机；脚本缺失时才尝试从 Web 下载。设备已撤销授权或卸载完成时网络中断，后台可能无法收到回执，此时不能假报后台已确认。单纯“撤销接入”不删除 Windows 文件。

当前验证包括服务端登记/任务/卸载状态、设备凭据加载逻辑、真实浏览器交互及官方 PowerShell 解析器语法检查。2026-10-16 已在用户正在使用的新 Windows 上完成实际安装、DPAPI 凭据读取、首次桌面截图，以及从 Web 发起的新截图任务回传；连接使用 HTTPS。2026-10-16 22:58 在同一台 Windows 上从 Web 发起完全卸载，39 秒后收到清理回执；本机核对计划任务已删除、节点目录已清空（当时仅留空的上级目录，脚本已改为最后一个节点卸载后一并删除）。

### 已有 SSH 的兼容接入

第一次接入需要在目标 Windows 上建立可信入口；未配置的电脑无法凭空远程执行初始化。

1. 在控制端生成该机器专用 SSH 密钥，私钥留在仓库外，把公钥复制到 Windows。
2. 在目标用户自己的管理员 PowerShell 中运行仓库提供的引导脚本（不要使用另一个管理员账户代运行）：

   ```powershell
   .\windows_desktop_bootstrap.ps1 -PublicKey 'ssh-ed25519 AAAA... litecode'
   ```

   默认 SSH 防火墙仅放行本地子网。异地直连需用 `-RemoteAddress` 指定控制端或跳板机地址，并配置实际可达的路由／端口映射。
3. 重新登录 Windows，确保 Python 真实解释器可用、目标用户桌面已登录，微信已安装。
4. 在 LiteCode 用 `ssh_save_host` 保存别名、地址、用户名、私钥路径；需要跳板时填写 `jump`。虚拟机的 `127.0.0.1` 地址指跳板机侧的回环地址。
5. 对话里说“初始化 新别名 并截图验收”，由工具安装依赖和实际截图。之后直接使用对话操作。

控制端也可生成包含专用公钥的一行命令，无需手工复制脚本。容器中先提供新机器实际地址、账户和跳板，然后运行：

```bash
PYTHONPATH=/opt/litecode:/opt/litecode/core python3 -m lib.windows_onboarding --alias win-new --host 192.168.11.73 --user litecode
```

模块在工作区 `.secrets/windows_keys/` 生成专用私钥并保存主机别名，输出 `uploads/windows-onboarding/win-new/初始化命令.txt`。目标用户在管理员 PowerShell 中粘贴该文件的一行命令，即执行完整引导；控制端再调用 initialize 连接验收。无新机器地址时不创建虚假可用主机。当前已验证命令编码与参数转义，尚未在全新系统做完整安装验收。

这是“一次本机引导，后续对话初始化”。脚本尚未在全新 Windows 上验收，不能宣称所有新机器一键接入已通过。

## 当前边界

Windows 已登录且未锁屏才可操作桌面；SSH 后台会话本身不能操作登录界面。工具使用已保存别名对应的 Windows 账户及其现有权限，没有额外提升权限。当前 win11 的注册表已配置 `litecode` 自动登录；本轮读取了配置状态，没有重启验收或改动 UAC。应用扫码由用户在手机完成。`wechat_status` 是按需检查，尚无常驻的自动登录通知。任务目录保留用于诊断，当前不自动清理。

默认交互任务使用 Limited；用户已授权处理高权限窗口时可传 `elevated=true`，以该账户可用最高权限启动，不更改 UAC 或账户权限。当前用户已明确授权最高权限。关闭全部窗口前先停用会打开窗口的巡检任务，避免关闭后被巡检重新唤起。

核心 handler 第二返回位在现有 agent 中用于 diff_view。图片通过 `_add_artifact` 单独登记，第二返回值保持 None，避免把图片对象写进代码 diff。前端历史及流式 diff 仅渲染字符串，兼容旧记录中的异常图片对象。

Web 页面载入新版脚本后，会在空闲时每5秒检查后台新轮次，只追加该轮的新消息并接上SSE，不重新渲染整段旧历史。定时巡检即使在关闭浏览器后也会运行；重新打开原会话可查看保存结果。
