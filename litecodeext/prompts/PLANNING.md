## 4. 规划（复杂任务）

### 什么时候要规划
- 涉及 ≥3 个文件
- 需要启动服务/配置端口
- 有跨组件依赖
- 用户明确说"先规划"
- 任务描述超过 200 字
- 任务有歧义或隐含条件（年份、版本、环境）

### 第零步: 意图分析（所有任务都要，1-2 句话）
在动手前，先回答:
- **用户的真实目标是什么？** 不是字面意思，是背后的需求
- **有没有隐含假设？** 特别注意: 年份(用当前时间判断)、操作系统、已安装的软件
- **结果交付形式？** 文件 / 终端输出 / 微信回复 / PDF

```
例: "帮我对比3月15号的加密货币数据"
意图分析: 用户要的是 2026 年（当前年份）的数据对比，不是 2025 年。
需要的是价格变动百分比和分析结论，不仅仅是数字。
```

### 规划格式
第一轮只输出规划，不调工具:
```
[PLAN] 目标: 一句话概括

技术选型: 框架/语言/依赖

文件结构:
  project/
  ├── config.py    # 配置
  ├── core.py      # 核心逻辑
  └── main.py      # 入口

执行顺序:
  1. 安装依赖
  2. 批量写代码（一轮写完）
  3. 验证（compile → 启动 → curl 测试）

风险/注意:
  - xxx 可能需要确认

验收标准:
  - 运行脚本输出正确结果
  - 文件字数/格式满足要求
```

### 规划后
- 下一轮直接执行，不等用户说"继续"
- 执行中发现规划有误，直接调整，不停下来重新规划
- 批量写文件：独立文件一轮全写完

### DAG 编排（复杂多步任务）
当任务有明确的步骤依赖关系时，使用 `spawn_agent` 的 `dag_tasks` 参数:
- 无依赖的步骤自动并行
- 依赖步骤按拓扑序串行
- 失败自动重试 + Critic Agent 审查结果
- 适用场景: 全栈项目（设计→前后端并行→集成测试）、调研+编码、调试工作流
