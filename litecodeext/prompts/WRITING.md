## 7. 长文创作规范

### 适用范围
小说、长篇报告、系列文章、技术文档集、剧本、论文——一切需要跨章节/跨段落保持一致性的长文本。

### 核心流程

```
用户需求 → 结构规划 → 状态文件初始化 → 分批创作 → 状态更新 → 循环
```

### 第一步：结构规划（第一轮只输出大纲，不调工具）

输出格式：
```
[OUTLINE]
title: 书名/报告名
total_chapters: N
target_words: M

chapters:
  1. 标题 | 核心情节/要点 | 目标字数
  2. ...
```

### 第二步：初始化 story_state.json

每个长文项目必须有状态文件，结构如下：

```json
{
  "title": "项目名",
  "type": "novel|report|series",
  "current_chapter": 0,
  "total_chapters": 80,
  "characters": {
    "角色名": {
      "identity": "身份描述",
      "traits": ["特征1", "特征2"],
      "skills": ["技能1"],
      "relationships": {"其他角色": "关系"},
      "status": "当前状态",
      "first_appear": 1
    }
  },
  "plot_events": [
    {"chapter": 1, "event": "一句话概括"}
  ],
  "world_rules": {
    "核心设定1": "描述",
    "核心设定2": "描述"
  },
  "style_guide": {
    "tone": "轻松幽默/严肃/学术",
    "pov": "第一人称/第三人称",
    "special_rules": ["不使用某种表达", "固定句式"]
  },
  "consistency_notes": [
    "武功名称统一用xxx",
    "地名统一用xxx"
  ]
}
```

### 第三步：分批创作

每章/每段创作前，必须：
1. `read_file story_state.json` — 加载当前状态
2. 将状态摘要注入到写作 context 中
3. 写完后立即更新 story_state.json

写作 context 注入模板：
```
## 当前状态（必须保持一致性）

### 已有角色
{characters 的精简摘要}

### 最近情节（最近 3 章）
{plot_events 最后 3 条}

### 世界规则
{world_rules}

### 本章要求
- 章节号: N
- 标题: {outline[N].title}
- 情节要点: {outline[N].summary}
- 约 3000 字

### 一致性检查清单
{consistency_notes}
```

### 第四步：写完一章后更新状态

```python
# 更新 story_state.json 的内容：
# 1. current_chapter += 1
# 2. 新角色 → 加入 characters
# 3. 本章事件 → 加入 plot_events
# 4. 角色状态变化 → 更新 characters[name].status
# 5. 新的一致性规则 → 加入 consistency_notes
```

### 质量标准

- **一致性 > 文采**：宁可写得朴素也不要前后矛盾
- 角色不能在 A 章会某技能，B 章又不会
- 地名、人名、术语全文统一
- 时间线不能跳跃或倒退（除非闪回，需标注）
- 每章结尾要有悬念或过渡，不能硬切

### 章节标题格式 (必须严格统一)

- 每一章 **首行** 写作 `# 第N章：标题` (中文全角冒号, 章号用中文数字)
- 本项目所有章节的分隔符必须一致 (要么都用「：」要么都用空格, 不要混)
- `story_state.json` 的 `current_chapter` 必须和文件名 / 内部标题三处一致
  - 例: `chapter_02.md` 首行不能是 `# 第一章：xxx` (章号错位即 bug)
- 写完一章后先 `head -1 chapter_NN.md` 确认标题章号正确, 再更新 state

### 字数验证

**禁止用 `wc -m` 验证中文字数**（它统计的是字符数，含标点空格 markdown 符号，会虚高 30-50%）。

正确方法：
```bash
python3 -c "
import re, sys
text = open(sys.argv[1]).read()
cn = len(re.findall(r'[\u4e00-\u9fff]', text))
total = cn + len(re.findall(r'[a-zA-Z]+', text))
print(f'中文字数: {cn}, 总词数(含英文单词): {total}')
" /path/to/file.md
```
- 用户要求的"字数"默认指中文汉字数 + 英文单词数
- 如果不足要求字数，必须补充内容后重新验证

### 禁止

- 禁止不读 story_state.json 就开始写
- 禁止写完不更新 story_state.json
- 禁止一次写超过 5000 字（超过就拆分）
- 禁止跳过大纲中的章节
- 禁止在主 Agent 循环中直接 write_file 写长文内容（必须用 spawn_agent(writer)）

### 反 AI 味道清单 (实测血泪, 必须遵守)

**禁止的心理描写格式**
- ❌ `【卧槽...】`、`【爽！】`、`【这也太...】` — 中括号系统消息式心理描写是 AI 味最重的标志
- ✅ 用 `他心想: xxx`、`暗骂一声`、`心里咯噔一下`、或者直接内独白不加标签

**禁止的套话黑名单** (出现频率超过 1 次/章就要重写)
- 「瞳孔一缩」、「冷笑一声」、「不可置信」、「眼神变得冰冷」
- 「缓缓打开，散发着神圣的光芒」、「一股庞大的信息流」
- 「接下来」、「然而」、「综上所述」、「值得一提的是」、「不得不说」、「必须指出」
- 「表面上...实际上...」同句式连续 2 次
- 结尾永远是"望向远方眼神坚定" / "握紧拳头默默发誓"

**禁止的系统式语言**
- 禁止引用原作: `【记载在《xxx》中】`、`【按照原剧情】` — 角色不应该知道自己在小说里
- 除非题材就是"穿书" (且已在 world_bible 登记), 否则主角不能"知道剧情"
- 金手指提示文案要"润色"成角色感觉, 不要写成 `【获得技能X】` 这种游戏 UI 语言

**节奏检查**
- 每章 ≥ 3 种场景元素: 对话 + 动作 + 环境描写 + 内心戏 + 冲突
- 连续 3 段只有对话 → 补环境或动作
- 连续 3 段只有内心戏 → 补对话推进剧情
- 段落长度交错: 长段铺垫 + 短段爆点, 不要段段 50 字

**数值/设定核对**
- 新出场角色: 立刻登记进 characters (写武功/外貌/性格三要素)
- 用到已有角色: 先查档案, 不能凭记忆写其技能/关系
- 武功 / 金手指: 不能凭空改规则, 改设定要走 `world_bible.md` 更新流程
