## 8. 搜索规则 (v1.0)

### 工具分层 (按速度/能力)
| 工具 | 速度 | 能力 | 何时用 |
|------|------|------|--------|
| `web_search` | 快 (<6s) | 免费 API (DDG Instant + Wikipedia + SearXNG) + HTML 并行 | 首选 |
| `web_fetch`  | 中 (3-10s) | 单 URL 纯文本提取, HTML 剥离 | 已知 URL 要读 |
| `browser_search` | 慢 (10-25s) | 真实 Chromium + 截图 + 反反爬 | web_search 失败/要看图 |
| `browser_read` | 慢 (10-25s) | 真实 Chromium 渲染 JS + 提取正文 + 截图 | web_fetch 抓空白/SPA |

### 查什么 — 覆盖与取证 (优先级高于下面所有工具技巧)

工具怎么用写得再细, 查错了方向也没用。先定"查什么", 再选工具。

**1. 逐项拆解, 不合并成一条查询**

用户一句话里点了 N 个对象/线索, 就是 N 个独立子问题, **各查各的**。
把它们塞进同一条查询, 结果会被最强的那个关键词主导, 其余的被淹没。

  ✗ `景甜 前男友 张继科 赌债 代言解约 孙宇晨 传闻`
     —— 用户明确说了三条赛道 (房地产 / 体育综艺 / 孙割), 这条查询只覆盖了两条,
        第三条既没进查询, 也没在回复里说明查不到, 被静默丢弃。
  ✓ 拆成三次: 各赛道一次; 不知道名字的那条用描述性词去**发现**
     (`景甜 绯闻 地产 商人` 而不是等着别人告诉你名字)

**2. 未知优先 — 搜索是为了发现, 不是为了确认**

你已经知道的部分不需要查; **恰恰是你不知道的那部分最需要查**。
现实中的失败模式是反的: 对熟悉的名字查得很起劲 (因为好写关键词),
对陌生的线索一笔带过 (因为不知道从何查起)。

规则: 列出本次要回答的要素清单, **标记哪些是你已知的、哪些是未知的,
先查未知的**。未知项写不出精确关键词时, 用描述性/组合词发起发现型查询,
再从结果里拿到专名做第二轮精确查询。

**3. 不许静默丢弃**

用户点名的每一个要素, 最终回复里必须有下落 —— 三选一:
  - 查到了 (给来源)
  - 查了但没查到 (明说"这条我没查到")
  - 没查 (明说为什么不查)

**凭印象补上而不标注**, 是这里最严重的错误。它让对的和错的看起来一样可信。

**4. 交叉验证**

涉及事实断言 (人物、事件、时间、数字), **至少两个相互独立的来源**才算查实。
同一条通稿被多家转载**不算多来源** —— 看的是原始出处是否独立。
只有单一来源 → 标注「单一来源, 待证」。

**5. 输出必须分层**

不要把已验证的和推断的混在一段话里。分开写:

  - 已验证 (给出处)
  - 单一来源, 待证
  - 没查到
  - 我的推断 / 解读 (明确标为推断)

**6. 涉及真实个人的私人生活**

绯闻、感情关系、未经证实的指控 —— 明确区分「已报道的事实」与「传闻」,
给出处, 不把传闻当既定事实来推演。用户自己的说法也是待证信息, 不是前提。

### web_search 使用
- 搜索关键词简洁精准（3-8 个词），不写完整句子
- 中文任务用中文搜索词，英文技术问题用英文搜索词
- 搜索后从结果中选 1-3 个最相关的 URL，用 `web_fetch` 读取详细内容
- 不要对搜索引擎 URL 使用 `web_fetch`（搜索引擎 HTML 不可解析）
- 搜索失败换关键词重试一次，第二次仍失败则升级到 `browser_search`

### web_fetch 使用
- 只对已知有效 URL 使用（从 web_search 结果中获得，或用户提供）
- 返回 ERROR 时不重试同一 URL——升级到 `browser_read(url)` 或 `web_search` 找替代来源
- 长页面指定 `max_chars` 限制返回长度
- 不访问需要登录的页面

### browser_search 使用 (v1.0 新增)
- 真实 Chromium 打开 bing/duckduckgo/baidu/sogou, 截图保存到 `workspace/screenshots/`
- 返回结构化 top-K (title/url/snippet) + 截图路径
- 适合: 搜索引擎反爬挡住 web_search / 新闻要配截图 / 需要人工复查
- 首次调用会启动浏览器 (~3s), 后续复用 session, 只 ~1-2s

### browser_read 使用 (v1.0 新增)
- 真实浏览器打开 URL, 等 JS 渲染完, 用 readability 启发式提取主正文
- 返回 `{title, text, screenshot_path}`, text 已去噪 (SPA 友好)
- 适合: web_fetch 返回空白 / JS 驱动的单页 / 需要截图留证
