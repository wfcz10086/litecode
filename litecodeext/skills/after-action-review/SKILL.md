# 复盘 (After Action Review)

复盘的唯一目的: **下次做得更好**。不是追责, 不是写成绩单。
核心纪律: **把决策质量和结果好坏分开** —— 好决策也可能撞上坏运气, 烂决策也可能侥幸成功。只看结果复盘, 会学到错误的教训。

## 第 0 步: 收集材料 (缺了先问)

- 原本的目标与成功标准 (当时怎么定的, 不是现在回头想的)
- 实际结果 (数字)
- 关键时间点和当时做的决定 (聊天记录、文档、提交记录、日志都可以; 用户给了文件就读)
- 参与者

## 第 1 步: 四个基本问题 (美军 AAR 原型)

| 问题 | 内容 |
|---|---|
| 1. 原本期望发生什么? | 目标、标准、计划 |
| 2. 实际发生了什么? | 只写事实和数字, 不评价 |
| 3. 为什么有差异? | 见第 3 步 |
| 4. 下次怎么做? | 见第 4 步 |

## 第 2 步: 时间线

| 时间 | 事件/决定 | 当时掌握的信息 | 当时的考虑 | 事后看 |
|---|---|---|---|---|

"当时掌握的信息"一栏是关键: 评判决定只能用**当时能知道的**信息, 防止后见之明。

## 第 3 步: 差距分析

### 3a. 决策质量 × 结果 四象限

对每个关键决定归类:

| | 结果好 | 结果坏 |
|---|---|---|
| **决策好** (信息充分、过程合理) | 应得的成功 → 固化下来 | 坏运气 → 不要乱改流程, 看能否降低风险暴露 |
| **决策差** | 侥幸 → **最危险**, 必须改 | 应得的失败 → 改 |

### 3b. 根因 (问到可行动为止)

对每个"决策差"或"执行差"的点连问"为什么", 直到落到一个**可以改变的流程、信息、能力或约束**为止 (通常 3~5 层)。
- 停在"某人粗心"不合格 —— 继续问: 什么样的流程让粗心能造成这么大影响?
- 分清: 信息不足 / 判断失误 / 执行偏差 / 外部不可控。

## 第 4 步: 保持 / 改进 / 停止

| 类型 | 内容 | 证据 |
|---|---|---|
| 保持 (做对了, 要固化) | | |
| 改进 (做了但要换方式) | | |
| 停止 (不该再做) | | |
| 开始 (下次新增) | | |

至少写 2 条"保持" —— 只找问题的复盘会让人以后不愿复盘。

## 第 5 步: 行动项 (不超过 5 条)

| 行动 | 负责人 | 截止日期 | 怎么算完成 | 防止复发的机制 (清单/自动化/检查点) |
|---|---|---|---|---|

优先选"改机制"的行动 (加检查清单、加自动告警、改默认值), 少选"以后注意"——"以后注意"不算行动项。

## 输出模板

```markdown
# 复盘: <事件名>  (日期, 参与者)
## 一句话结论
## 目标 vs 结果
## 时间线
## 关键决定评估 (四象限)
## 根因
## 保持 / 改进 / 停止 / 开始
## 行动项
## 学到的可迁移经验 (1~3 条, 写成以后能直接用的规则)
```

## 纪律

- **无责**: 描述用"决定/流程/信息"做主语, 不用人名做主语; 团队复盘时先声明这一点。
- 事实与解释分开写; 没有证据的推测标"推测"。
- 个人复盘 (投资、考试、求职) 同样适用, 第 3a 步最有用: 赚钱了不代表判断对。
- 复盘完问用户是否要把"可迁移经验"记进记忆 (save_memory), 下次类似决定时调出来。
