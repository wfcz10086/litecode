# 加权决策矩阵

决策矩阵的价值不在"算出一个分数", 而在三件事:
1. 逼人把**标准和权重**说出来 (很多纠结其实是没想清楚自己最看重什么);
2. 看清**结论有多脆弱** (权重稍微一变就翻转 = 分数帮不了你);
3. 和**直觉对照** (算出来和心里想的不一样时, 那个落差就是信息)。

```bash
M="python3 ${LITECODE_HOME:-/opt/litecode}/skills/decision-matrix/scripts/matrix.py"   # 只用标准库
```

## 第 1 步: 选项 (3~6 个)

把用户提到的选项列出, 并主动补: "维持现状" 和 "组合/折中方案" (例如先兼职再全职)。选项超过 6 个先用一票否决线筛。

## 第 2 步: 标准 (4~7 个) 与一票否决线

- 标准要**互不重叠** ("薪资"和"总收入"只留一个)、**可判断** ("发展好"要改成"两年内能带团队的可能性")。
- 先问用户有没有**底线**: 低于某个水平无论其他多好都不要 → 写成 `veto` (一票否决)。
- 典型遗漏: 可逆性/退出成本、对家人的影响、学习价值、执行难度、风险上限。

## 第 3 步: 权重 —— 由用户定

权重是价值判断, **不能由 AI 拍脑袋**。做法: 给用户 100 分让其分配; 用户嫌麻烦时, 先给一个建议并标明"这是我的猜测, 请改"。
检查: 如果某个标准权重 > 50%, 问一句"那其实是不是只看这一条就够了?"

## 第 4 步: 打分 (1~5) 并写依据

| 选项 | 标准 | 分 | 依据 (事实/数据/估计) | 把握 |
|---|---|---|---|---|

- 依据栏必填。"估计"类要标明, 把握 = 高/中/低。
- 能查到的数据用 web_search 查 (薪资水平、价格、评价), 不编造。
- 把握低又权重高的格子 = **最值得花时间去查清的信息**, 单独列出来。

## 第 5 步: 跑脚本

写 JSON 到工作目录 (如 `$WORKSPACE/decision/matrix.json`):

```json
{
  "scale": 5,
  "criteria": [
    {"name": "收入", "weight": 25},
    {"name": "成长", "weight": 35},
    {"name": "通勤", "weight": 15, "veto": 2},
    {"name": "稳定性", "weight": 25}
  ],
  "options": {
    "A公司": {"收入": 4, "成长": 3, "通勤": 4, "稳定性": 4},
    "B公司": {"收入": 3, "成长": 5, "通勤": 2, "稳定性": 3},
    "留在现职": {"收入": 3, "成长": 2, "通勤": 5, "稳定性": 5}
  }
}
```

```bash
$M $WORKSPACE/decision/matrix.json          # 中文表格
$M $WORKSPACE/decision/matrix.json --json   # 机器可读
```

输出包含: 排名、被否决项、"第二名在什么权重下反超第一名"、权重随机扰动 ±30% 下各选项拿第一的比例。

## 第 6 步: 解读 (必须做, 不能只贴分数)

1. **稳健度**: 第一名拿第一比例 ≥ 80% → 结论稳; 55%~80% → 取决于权重, 请用户重新确认关键权重; < 55% → 基本平手, 明说"分数帮不了你, 要回到你最在乎什么"。
2. **翻转点**: 哪个标准的权重只要小幅变化就翻转? 那个标准就是真正的争议点。
3. **直觉对照**: 问用户"看到结果, 你是松了口气还是有点失望?" 失望通常说明有个没写进表的标准 (面子、某个人、某种向往), 把它加进去重算。
4. **信息价值**: 列出"把握低 × 权重高"的格子, 建议先查清再决定。

## 输出模板

```markdown
## 选项与否决线
## 标准与权重 (注明: 权重由用户确认 / 待确认)
## 打分表 (含依据与把握)
## 计算结果 (脚本输出)
## 解读: 稳健度 / 翻转点 / 直觉对照
## 先去查清的信息 (按价值排序)
## 建议与把握度
```
