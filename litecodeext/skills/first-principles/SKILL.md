# 第一性原理拆解

类比思维: "别人这么做 → 我也这么做, 稍微改一点"。
第一性原理: "这件事在不能再拆的层面上受什么约束 → 在约束内最好的做法是什么"。
本技能把它变成 6 步可执行流程。**每一步都要写出来, 不能只在脑子里过。**

## 第 1 步: 写清目标, 而不是手段

把用户的问题改写成"要达成的结果 + 衡量指标"。

| 用户原话 (手段) | 改写后 (目标) |
|---|---|
| 我要招 3 个销售 | 下季度新增 50 个付费客户, 获客成本 < X |
| 要不要买更大的服务器 | p95 响应 < 300ms, 月成本 < Y |

如果改不出指标, 先停下和用户确认, 否则后面都是空转。

## 第 2 步: 列出当前方案里的全部假设

逐条写, 越多越好, 典型来源:
- "一直都是这样做的" (惯例)
- "行业都这样" (类比)
- "客户就是要 X" (未验证的需求)
- "这个成本就是这么高" (报价当成本)
- "必须由人来做 / 必须买成品" (形态锁定)

## 第 3 步: 逐条追问, 分成三类

对每条假设问: **凭什么? 证据是什么? 如果它不成立会怎样?**

| 假设 | 类型 | 依据 | 若不成立的影响 |
|---|---|---|---|
| ... | 硬约束 / 软约束 / 纯惯例 | 物理定律、法规、合同、数据... | ... |

- **硬约束**: 物理、数学、法律法规、已签合同、人的生理极限。不可违背, 但要核实是否真的存在。
- **软约束**: 预算、时间、团队技能、现有系统。可以花钱/花时间改变。
- **纯惯例**: 没有依据, 只是习惯。→ 这里是创新空间。

## 第 4 步: 落到最底层的数字

把对象拆成组成部分, 用"原材料价 / 理论下限"对比"市场价 / 现状":

```
对象: ________
组成部分        现状成本/耗时    理论下限 (依据)     差距倍数
部件A           ...             ...                 ...
部件B           ...             ...                 ...
合计            ...             ...                 ...
```

差距倍数大的地方 = 值得重做的地方。理论下限的依据必须写出 (报价单、原材料行情、公开数据), 查不到就标"估算"并写估算过程。需要查数据时用 web_search, 不要编数。

## 第 5 步: 从约束重新组合方案

只保留硬约束, 问:
1. 如果从零开始、没有历史包袱, 最直接满足目标的做法是什么?
2. 能不能删掉某一步? (最好的部件是不存在的部件)
3. 能不能换一种形态满足同一个目标? (自建 vs 买、人工 vs 自动、一次性 vs 订阅)

给出 2~3 个重组方案, 每个写: 核心思路 / 依赖的关键假设 / 粗略成本或收益估算。

## 第 6 步: 最小验证实验

每个方案配一个能在 1~2 周内、低成本验证核心假设的实验:

| 方案 | 要验证的关键假设 | 实验做法 | 成功标准 (数字) | 成本 |
|---|---|---|---|---|

## 输出模板

```markdown
## 目标与指标
## 假设清单 (硬约束 / 软约束 / 纯惯例)
## 底层拆解 (现状 vs 理论下限)
## 重组方案 (2~3 个)
## 最小验证实验
## 我不确定的地方 (哪些数字是估算, 哪些约束没核实)
```

## 常见误用 (要主动避开)

- 把"第一性原理"当口号, 只说"回归本质"而没有拆出数字。
- 把软约束当硬约束 ("我们没预算" 不是物理定律)。
- 把硬约束当惯例 (法规、安全要求不能为了"颠覆"而无视)。
- 拆完不落地: 每次必须以"最小验证实验"结尾。
