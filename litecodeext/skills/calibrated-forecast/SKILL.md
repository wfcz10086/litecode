# 概率与基础比率校准

人对"这次"的判断几乎总是太乐观、太自信。纠正方法很朴素: **先问同类事情通常怎样, 再看这次有什么不同。**

```bash
F="python3 ${LITECODE_HOME:-/opt/litecode}/skills/calibrated-forecast/scripts/forecast.py"   # 只用标准库
```

## 第 1 步: 把问题改成可裁决的

模糊: "这个项目能成吗?"
可裁决: "**到 2027-06-30**, 这个 App 的**月活是否 ≥ 1 万**?"
必须有: 截止时间 + 明确判定标准 + 谁来判定/看什么数据。改不出来就先和用户对齐。

## 第 2 步: 外部视角 —— 找参照类和基础比率

1. 列 2~3 个参照类 (宽窄不同): 例 "所有新 App" / "同赛道独立开发者 App" / "有 1000 粉丝起步的独立 App"。
2. 每个参照类找基础比率, 用 web_search 查, **写出处**; 查不到就写"估计"和推算过程。
3. 参照类之间差异大时, 说明选哪个作为锚点、为什么。

| 参照类 | 基础比率 | 来源 | 与本案相似度 |
|---|---|---|---|

## 第 3 步: 内部视角 —— 按证据调整

对每条具体证据问: **"如果结论为真, 我看到这条证据的可能性, 是结论为假时的几倍?"** 这就是似然比 (LR)。

| 证据 | 为真时出现的概率 | 为假时出现的概率 | 似然比 | 备注 |
|---|---|---|---|---|
| 团队之前做成过同类产品 | 0.5 | 0.2 | 2.5 | |
| 已有 50 人付费预订 | ... | ... | ... | |

经验: 绝大多数现实证据的 LR 在 0.5~3 之间; 写出 ≥5 的要再三确认。**不相关的细节 LR = 1, 别被生动故事带跑。**

```bash
$F update --prior 0.15 --lr 2.5 --note "团队做成过同类" --lr 1.5 --note "已有预订" --lr 0.7 --note "赛道巨头刚入场"
```

## 第 4 步: 给出概率 (带区间, 避开 0 和 100)

```markdown
## 预测
问题: <可裁决版本>
概率: 28% (合理区间 18%~40%)
锚点: <参照类> 基础比率 15%
上调因素: ... ; 下调因素: ...
最大不确定性: ...
会让我上调的信号: ... (具体到数字/事件)
会让我下调的信号: ...
下次更新时间: ...
```

规则:
- 概率写到 5% 精度即可, 不要假精确 (37.4%)。
- 不写 0% / 100%, 极端也写 2% / 98%。
- 多人或多方法估计不一致时: `$F combine 0.3 0.45 0.2`, 先找分歧来源再合并。

## 第 5 步: 记录与复盘校准度

把预测记进 CSV (prob,outcome,label), 结果揭晓后填 outcome (1 发生 / 0 未发生):

```bash
$F brier $WORKSPACE/forecasts.csv
```

看分桶表: 你说 70% 的事, 实际发生约 70% 才叫校准; 实际只发生 40% = 过度自信。积累 20 条以上才有意义。

## 常见陷阱 (逐条自检)

- [ ] **规划谬误**: 工期/预算估计, 先看同类项目的实际超支比例 (通常超支 50% 以上很常见), 再定自己的数。
- [ ] **合取谬误**: 计划要 5 步都成功, 每步 80% → 整体只有 33%。把每步概率相乘。
- [ ] **故事越具体越可信**: 细节越多, 真实概率越低, 而不是越高。
- [ ] **只看成功者**: 参照类里有没有把失败者也算进去? (幸存者偏差)
- [ ] **新证据不动**: 出现了重要新信息, 概率却一点没变 = 锚定了。
