# 红队 / 反方论证

目的不是"否定", 而是在现实替你否定之前, 先用最强的反对意见压测一遍。
**态度要求**: 对事不对人; 只攻击论证, 不攻击动机; 反对要具体到能被验证或反驳。

## 第 1 步: 钢人化复述 (Steelman)

先用比用户本人更好的方式复述其观点, 结构化成论证链:

```
结论: ____
理由1: ____  (依赖的事实/数据: ____)
理由2: ____  (依赖的事实/数据: ____)
隐含前提: ____ (用户没说但必须成立的)
```

问用户: "这是你的意思吗? 有没有更强的理由我漏了?" —— 用户确认后再开打。用户说"直接开始"就跳过确认, 但复述仍要写出来。

## 第 2 步: 找最薄弱的一环

对论证链每个环节评估:

| 环节 | 类型 (事实/推理/前提/价值) | 证据强度 (强/中/弱/无) | 如果它错了, 结论还成立吗? |
|---|---|---|---|

"证据弱 + 一错结论就倒" 的环节 = 重点攻击目标。

## 第 3 步: 构造反方 (至少 4 种进攻角度)

1. **反例**: 找一个满足前提但结论不成立的真实案例 (需要时 web_search 查, 不编造; 查不到就明说是假想案例)。
2. **替代解释**: 同样的数据/现象, 有没有另一种完全不同的解释?
3. **基础比率**: 同类事情一般成功率多少? 凭什么这次例外? (结合 calibrated-forecast)
4. **对手视角**: 竞争者/监管者/用户/最了解情况的反对者会怎么回应?
5. **规模与时间**: 小规模成立, 放大 10 倍还成立吗? 一年后还成立吗?
6. **激励**: 谁在提供支持这个观点的信息? 他们有什么利益?

每条反方都要写成"**如果 X, 那么你的结论 Y 就不成立, 因为 Z**"。

## 第 4 步: 分级

| # | 反方论点 | 严重度 | 理由 | 可修补吗? 怎么补 |
|---|---|---|---|---|
| | | 致命 / 严重 / 可修补 / 小瑕疵 | | |

- **致命**: 成立则结论完全倒掉, 且目前无法反驳。
- 不要凑数: 没有致命问题就明说"没有发现致命问题", 不硬造。

## 第 5 步: 改主意条件 + 判决

```markdown
## 红队判决
- 最强反方论点: ____
- 原观点状态: 站得住 / 需修正后站得住 / 站不住
- 修正版观点: ____ (把可修补的问题补上后的版本)
- 什么证据会说服我改主意 (双方都要写):
  - 支持方若看到 ____ 应放弃原观点
  - 反方若看到 ____ 应承认原观点成立
- 最便宜的检验: ____
```

## 变体

- **"预审会"模式** (用户要去说服老板/投资人): 扮演最难缠的听众, 列出 10 个最可能被问到的尖锐问题, 按难度排序, 每个附建议答法和需要准备的数据。
- **"双人辩论"模式**: 正方、反方各写 3 轮, 每轮必须回应对方上一轮最强的点, 最后由中立裁判总结哪方在哪些点上胜出。
- **自我红队**: 对 AI 自己刚给出的建议做一次红队, 用户说"你刚才的建议有什么问题"时直接用本流程。
